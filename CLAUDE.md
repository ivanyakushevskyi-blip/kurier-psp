# Кур'єр: Хмельницький — інструкції для Claude

Хобі-гра для PSP (homebrew): кур'єр на сріблястому VW Golf V розвозить замовлення справжнім центром Хмельницького.
Власник проєкту — Іван. Спілкування українською, коротко й по суті.

Повний дизайн-документ: `docs/design.md` (жива версія — Claude Docs, посилання там же). Перед роботою над етапом прочитай його.

## Головні правила

1. **Спершу узгодження, потім код.** Нові механіки, зміни стилю, великі рішення — спочатку обговорити з Іваном і записати в `docs/design.md`. Не робити «сюрпризів» поза поточним етапом.
2. **Етап готовий лише після перевірки на справжній PSP.** Іван тестує на PSP Street (E1000, 64 МБ, CFW). PPSSPP пробачає помилки, які залізо не пробачає.
3. **Впізнаваність міста важливіша за графіку.** 2D, вид згори під кутом, камера без обертання («північ угорі», як GTA 2). 3D відкладено.
4. Перед здачею збірки: прогнати `scripts/build.sh --host` і подивитись кадри в `build/frames` (Read на .ppm → конвертувати в png).
5. Іван отримує готовий архів `dist/KurierKhm_PSP.zip`; нагадуй, що на картці має бути саме `PSP/GAME/KurierKhm/EBOOT.PBP` без зайвих вкладених папок.

## Залізо PSP — перевірені на практиці пастки

- **Ініціалізація екрана.** Перший `sceDisplaySetFrameBuf` має бути з НЕкешованою адресою VRAM (`vbase | 0x40000000`) і `PSP_DISPLAY_SETBUF_NEXTFRAME`, далі кілька `sceDisplayWaitVblankStart`. Інакше на справжній PSP чорний екран (у PPSSPP працює). Робоча послідовність — у `main()` у `src/main.c`, не міняти без потреби.
- Малювати в буфер, якого зараз немає на екрані (подвійна буферизація), інакше видно напівнамальовані кадри.
- Не викликати `scePowerSetClockFrequency`: частоту Іван виставляє в CFW (333/166).
- Ресурси вбудовані в EBOOT як C-масив (`src/assets_data.c`, генерується). Асемблерний `.incbin` не використовувати.
- Шлях для збережень — поруч з EBOOT (з `argv[0]`).

## Структура

```
data/osm/        тайли OpenStreetMap центру (t0..t3.osm, bbox ≈ 26.982–27.008, 49.414–49.430)
ref/             референси: satellite.png (супутник тієї ж області), stylized.jpg, golf_v_silver.jpg
tools/           Python-конвеєр: mapgen.py (OSM → піксель-арт карта), sprites.py, bake.py (пакує ресурси), pal.py (палітра)
src/main.c       гра (C, PSPDEV); HOST-збірка (-DHOST) — автотест з дампом кадрів
scripts/         setup.sh (тулчейн + Python), build.sh (повна збірка)
docs/design.md   дизайн-документ і прийняті рішення
```

## Команди

```bash
./scripts/setup.sh                 # один раз на нове середовище (~170 МБ PSPDEV)
export PSPDEV=$HOME/pspdev PATH=$PATH:$HOME/pspdev/bin
./scripts/build.sh --host          # карта + ресурси + ПК-автотест (кадри в build/frames) + EBOOT у dist/
```

Нові дані OSM: `https://api.openstreetmap.org/api/0.6/map?bbox=<lon0>,<lat0>,<lon1>,<lat1>` (великі області — тайлами; Overpass з хмари нестабільний). Атрибуція «© OpenStreetMap contributors» має бути в грі.

## Поточний стан

- Є 2D-прототип (скутер, замовлення, мінікарта, назви вулиць) — він же стартова точка.
- Відомі проблеми прототипу: погане керування, застрягання в будинках, машина «їде по даху» замість ховатися за будинком, кольори дахів вигадані.
- Наступне: **етап 0** — зібрати прототип із цього репозиторію і підтвердити запуск на PSP Іванa; далі **етап 1 «Впізнаване місто»** (кольори/зелень із `ref/satellite.png`, висоти будинків, ключові місця).
